## 阶段目标

P9 建立租户隔离的运营洞察能力：版本化事件进入 `insight-service` 后先匿名化，再形成小时/日聚合、核心指标、趋势异常、问题雷达、投诉主题、知识缺口和受控自然语言查询。`mall` 继续作为订单、退款、物流和金额事实来源；P9 不保存完整订单或个人敏感资料。

## 并行端口约束

A/B/C 不得直接引用其他任务尚未合并的具体实现。每个任务在自己的包中定义最小端口：

```java
// P9-A：集成方持久化事实，并把事实变化送入 B。
public interface InsightFactSink {
    void append(AnonymizedFact fact);
}

// P9-B：集成方从持久化层读取指标，并供 C 的查询执行适配。
public interface MetricSnapshotReader {
    MetricSnapshot query(MetricQuery query);
}

// P9-C：AI 只能产生计划，执行仍由白名单语义层完成。
public interface ControlledQueryExecutor {
    QueryResult execute(String trustedTenantId, QueryPlan plan, QueryActor actor);
}
```

若必须连接其他任务，只提交本任务包内的端口、记录缺口，不创建跨任务临时 import，也不修改公共装配。

## 固定业务约束

- 所有事件先验证可信租户，再做 Inbox 幂等和匿名化。
- 原始事件 payload、完整订单和个人敏感资料不得落库、写日志或进入异常文本。
- 退款率和退款金额率使用订单归属周期口径；只有退款成功才进入分子。
- 满意度只使用显式用户评价，未评价只影响评价覆盖率。
- 小时增量、日终固化；7 天内自动滚动重算，超过 7 天进入人工重算清单。
- 雷达状态只允许 `OPEN -> ACKNOWLEDGED -> RESOLVED` 或 `OPEN -> IGNORED`。
- AI 只能命名和摘要聚类，不得改变聚类成员、风险类别或业务事实。
- 隐私、欺诈、监管、资金类主题必须主管审核。
- 自然语言计划禁止 SQL、表名、列名和任意表达式。
- P9 不提供跨租户行业基准，不自动创建或发布知识内容。

## 测试与数据清理

- 先写失败测试，再写最小实现；每个小任务单独提交。
- 定向测试后必须运行 `insight-service` 模块测试和 `git diff --check`。
- 测试租户、事件、雷达、主题、文档和 schema 使用 `test-` 或 `rag-test-` 前缀。
- 数据库集成测试由集成会话负责，完成后删除测试 schema 和测试数据。
- 不得通过禁用测试、放宽断言或跳过租户校验使测试通过。

## 会话交付格式

每个任务完成后必须报告：

1. 分支、工作区和最终提交 SHA。
2. 变更文件清单。
3. 实际执行的测试命令、测试数量和结果。
4. 测试数据清理结果。
5. 需要集成会话处理的契约、迁移、装配或跨服务缺口。

不得推送、创建 PR、合入其他分支或清理 Worktree。集成验收完成前保留任务分支和 Worktree。

## 合并门禁

集成会话按 `P9-A -> P9-B -> P9-C` 合并，并完成公共契约、Flyway、持久化适配、生产者、Gateway、前端入口和 E2E。根 Maven、前端构建、契约校验、空库迁移、租户隔离、重复投递、迟到修订、模型/MQ/`mall` 降级及全链路验收全部通过后，才允许通过 PR 合入 `master`。
